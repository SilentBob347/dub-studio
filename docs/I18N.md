# UI localization

The UI ships in six languages: en, ru, zh, es, pt, fr. English is the source language.

## Rules

- Every user-visible string in `frontend/src` goes through `t()` from `react-i18next`. No literals in JSX text, in
  `title` / `placeholder` / `aria-label` / `alt` attributes, in messages passed to `pushActivity` and friends.
- A new key is added to all six files in `frontend/src/locales/` in the same change, with a real translation.
  English text copied into another language is rejected by the tests unless the word is spelled the same in that
  language (allowlist below).
- Keys are typed: `src/i18next.d.ts` derives them from `en.json` with `strictKeyChecks`, so `npm run build` fails on
  an unknown key, also when a default value is passed. For dynamic keys build a union of literal keys or a
  `Record` from a closed set to keys (see `src/lib/gender.ts`); server values outside the set are normalized
  explicitly, never passed to `t()` as a raw string.
- Counts use i18next plurals: `key_one`, `key_other` (and `_few` / `_many` where the language needs them), called
  as `t("key", { count })`. Never write `item(s)`.
- Text that is data, not UI, stays as a literal: content-language endonyms (`DUB_LANGS`), brand names, units,
  key caps, file names.

## Tests (the gate)

`npm test` in `frontend/`:

- `tests/locales.test.ts` - every language has exactly the keys of `en` (plural groups aside), the plural
  categories of its language, no empty values, the same `{{placeholders}}` and markup tags; no Cyrillic outside
  `ru`; no value identical to English unless listed in `SAME_AS_EN`.
- `tests/noHardcodedText.test.ts` - parses `src/**/*.ts(x)` with the TypeScript compiler API and fails on JSX text
  with letters, on human-readable attributes and message calls given a literal, on English prose literals and on
  any Cyrillic literal, including one passed straight to a JSX attribute.
- `tests/scanHardcoded.test.ts` - fixtures for every violation kind and for the accepted forms, so a broken scanner
  cannot pass `noHardcodedText` vacuously.

Both allowlists live in `tests/i18nAllowlist.ts`. An entry that no longer matches anything fails the test, so the
lists cannot rot. Add an entry only for a token that is the same in every language (brand, unit, format name).

Server-side texts (progress lines, errors, component names) are not covered yet; they move to message codes
resolved in the UI.
